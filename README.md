# Ethan Vibes — starter project

A phone-friendly first version of Ethan Vibes: a colorful music/video catalogue with a private CEO login and R2 multipart uploads.

## Important before launch
- This is a starter project, not a completed security audit.
- Use content you own or have explicit permission to distribute.
- Never share your Cloudflare password, API tokens, CEO password, or secrets with anyone.
- Test with small non-sensitive files first.
- Cloudflare free-plan quotas and limits can change. R2 storage's free allowance is limited; large movies may require paid storage.
- The upload UI sends 8 MiB chunks through the Worker. This stays below the usual 100 MB Free-plan request body limit and uses R2 multipart upload. It is resumable only if the upload record and part progress are retained; this starter retries a failed part but does not yet provide a full "resume after closing browser" feature.

## Project structure
- `public/index.html` — public website and CEO dashboard UI
- `public/styles.css` — colorful mobile-first design
- `public/app.js` — browser logic
- `src/index.js` — Worker API, CEO authentication, R2 multipart uploads, public catalogue and media delivery
- `schema.sql` — D1 database schema
- `wrangler.toml` — Cloudflare Worker configuration template

## Setup from an Android phone
The easiest practical route is to use the Cloudflare dashboard's browser-based editor if available, or upload these files to a GitHub repository and connect it to Cloudflare. If the phone workflow becomes difficult, use a computer for the initial deployment; the site itself will still be manageable from your phone.

### 1. Create Cloudflare account
1. Open https://dash.cloudflare.com/ and create an account.
2. Verify your email and enable two-factor authentication if available.
3. Do not add a payment method unless you understand the plan and charges.

### 2. Create a D1 database
1. In Cloudflare dashboard, open Workers & Pages → D1 SQL Database.
2. Create a database named `ethan-vibes-db`.
3. Open its SQL console and run the contents of `schema.sql`.

### 3. Create an R2 bucket
1. Open R2 Object Storage and create a bucket named `ethan-vibes-media`.
2. Keep the bucket private; do not expose the bucket's S3 credentials in browser code.
3. Bind it to the Worker using the `MEDIA` binding shown in `wrangler.toml`.

### 4. Configure Worker
1. Create a Worker named `ethan-vibes`.
2. Upload/replace its code with `src/index.js` (or deploy via a Git-connected project).
3. Configure bindings named exactly `DB` (D1 database) and `MEDIA` (R2 bucket).
4. Set Worker variables/secrets:
   - `CEO_PASSWORD` is your strong CEO password, stored as an encrypted Worker secret.
   - `SESSION_SECRET` is a long random secret, at least 32 characters.
   - `SITE_ORIGIN` is your deployed site origin, for example `https://ethan-vibes.<your-subdomain>.workers.dev`.
5. Configure static assets from `public/` if deploying as a single Worker with assets; the provided `wrangler.toml` is a template and may need adjustment to match your dashboard deployment method.

### CEO password
Use a unique password at least 16 characters long, ideally generated by a password manager. Store it only as the encrypted `CEO_PASSWORD` Worker secret. Do not reuse your Cloudflare account password, and never put this value in website code or a public repository. Before a public launch, add rate limiting / bot protection and arrange a security review.

## Local / CLI deployment (requires a computer or terminal)
Cloudflare's recommended scaffold is `npm create cloudflare@latest`, then configure Worker assets and bindings. For deployment details, see:
- https://developers.cloudflare.com/workers/static-assets/
- https://developers.cloudflare.com/r2/objects/upload-objects/
- https://developers.cloudflare.com/workers/platform/limits/

## CEO-only upload security
- `/api/*` routes that change content require a valid signed session cookie.
- The R2 bucket is accessed only by the Worker; no R2 API keys are shipped to visitors.
- Public users can only see published media records.
- Uploads are staged as multipart objects and only appear in the catalogue after completion and publication.
- Use a unique strong CEO password and keep `SESSION_SECRET` private.

## Known limitations for this first starter
- Set up and test D1/R2 bindings and secrets before using the upload UI.
- Full "resume upload after closing/reopening the browser", robust rate limiting, image thumbnail generation, and production-grade password hashing should be added before a serious public launch.
- Streaming range requests are supported on a best-effort basis; test with your target browsers.
- R2 free storage is not enough for a large movie library. Monitor usage and billing.
